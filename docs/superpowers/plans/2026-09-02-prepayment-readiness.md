# 결제 연결 전 운영 준비 구현 계획

> 앞선 운영 준비 점검과 사용자의 전체 진행 승인을 구현 기준으로 사용한다.

## 1. 공개 자산 보안

- 공개 원본 이미지 라우트의 경로·MIME 검증 실패 테스트를 추가한다.
- 기존 Storage 경로 헬퍼를 사용해 다른 스케치북 객체 접근을 차단한다.
- 검증 오류는 안전한 상태 코드와 메시지로 정규화한다.

## 2. 생성 및 관리 인증 안전성

- 공개 ID가 충분한 엔트로피를 갖고 충돌을 재시도하는 테스트를 추가한다.
- 관리 세션 생성 실패 시 생성된 데이터와 Storage 객체를 정리하는 테스트를 추가한다.
- 관리 PIN 실패 횟수 갱신을 Firestore 트랜잭션으로 변경하고 동시성 테스트를 추가한다.
- 공개 생성·제출 API의 예상하지 못한 오류 메시지를 일반화한다.

## 3. 결제 안전 경계

- 환경 기반 결제 모드 판정 테스트를 추가한다.
- production에서 모의 결제를 거부하고 기본 모드를 비활성으로 둔다.
- 관리 화면과 공유 화면이 비활성 상태를 정확히 안내하도록 수정한다.
- 실결제 전환에 필요한 주문·승인·웹훅·취소·대사·환불·보존 항목을 런북에 기록한다.

## 4. 배포와 복구 준비

- 임시 Superpowers 산출물의 TypeScript include를 제거한다.
- CSP/HSTS를 기존 보안 헤더에 추가한다.
- GitHub Actions에서 Node 22, npm ci, lint, test, build, 에뮬레이터 통합 테스트를 실행한다.
- Firestore 인덱스와 백업/PITR/삭제 보호/알림/App Check 배포 절차를 런북에 기록한다.

## 5. 검증 및 인계

- 관련 테스트부터 전체 단위 테스트, 린트, 타입 검사, 빌드를 순서대로 실행한다.
- 에뮬레이터 통합 테스트와 모바일 E2E를 실행한다.
- 변경 UI를 정적 검사와 브라우저로 확인한다.
- 변경 사항을 검토한 뒤 하나의 Git 커밋으로 남긴다. 푸시와 배포는 하지 않는다.

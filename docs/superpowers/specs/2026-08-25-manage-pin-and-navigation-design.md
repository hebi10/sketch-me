# 관리 PIN 및 텍스트 메뉴 설계

## 목표와 범위

- 새 스케치북은 생성자가 정한 4자리 숫자 관리 PIN 없이는 관리 페이지와 관리 API에 접근할 수 없게 한다.
- PIN 힌트는 선택 입력이며, PIN을 잊었을 때 자동 복구나 관리자 문의 경로는 제공하지 않는다.
- 기존 공개/관리 화면의 우측 아이콘만 있는 행동을 텍스트가 있는 `☰ 메뉴`로 바꿔 행동의 의미를 분명히 한다.
- 친구가 보는 공개 페이지와 그림 작성 흐름은 계속 공개 상태로 둔다.

## 인증 흐름

1. 생성 폼의 이름 아래에 `관리용 비밀번호`(필수)와 `비밀번호 힌트`(선택)를 둔다.
   - PIN은 정확히 4자리 숫자만 허용한다. 숫자 키패드가 뜨도록 입력을 구성하고, 값은 마스킹한다.
   - 힌트는 40자 이하의 평문 안내 문구다. PIN 자체나 4자리 숫자를 넣지 않도록 안내한다.
2. 생성 API는 PIN을 적응형 단방향 비밀번호 해시로 저장하고, 힌트와 PIN 로그인 실패 상태를 스케치북 문서에 함께 저장한다.
   - PIN 평문, PIN이 들어 있는 복구 URL, PIN을 응답 본문에 포함하지 않는다.
3. 새 스케치북의 `/m/{publicId}` 및 하위 관리 경로는 인증 쿠키가 없을 때 `관리용 비밀번호 입력` 화면으로 이동한다.
   - 힌트가 있으면 "힌트: …"를 한 번에 읽을 수 있는 보조 문구로 보여 준다.
   - 맞는 PIN을 입력하면 `httpOnly`, `sameSite=lax`, `secure`(운영) 관리 세션 쿠키를 30일간 발급한다.
   - PIN 자체를 URL, localStorage, 화면 상태 복원 데이터에 보관하지 않는다.
4. PIN은 스케치북별·접속 출처별로 5회 연속 실패하면 10분 동안 입력을 잠근다.
   - 잠금 중에는 남은 시간을 알리고 입력을 비활성화한다.
   - 성공한 입력은 실패 횟수를 초기화한다.
5. `관리용 비밀번호를 잊으셨나요?`는 "복구할 수 없어요. 새 스케치북을 만들어 주세요."만 표시한다. 문의 링크, 이메일 수집, 비밀번호 재설정은 추가하지 않는다.
6. 생성 완료 화면에서는 기존 `관리 복구 링크`를 제거한다. 관리 페이지 진입 버튼만 제공한다.

## 기존 데이터와 호환성

- PIN 해시가 없는 기존 스케치북은 현재의 고엔트로피 관리 쿠키와 복구 링크를 계속 허용한다. 기존 사용자를 갑자기 잠그지 않는다.
- 기존 소유자가 관리 대시보드를 열면 `관리용 비밀번호 설정하기`를 한 번 안내한다. 설정 완료 후에는 PIN 세션을 새 기준으로 사용하며, 예전 복구 링크는 더 이상 세션을 발급하지 않는다.
- 새 스케치북은 기존 관리 토큰을 외부에 노출하거나 복구 링크로 반환하지 않는다. 관리 세션은 PIN 검증 후에만 만든다.

## 메뉴와 화면 구조

### 공개 페이지 `/s/{publicId}`

- 오른쪽의 연필 아이콘을 `☰ 메뉴` 텍스트 버튼으로 바꾼다. 왼쪽 홈 이동도 `홈` 텍스트와 화살표를 함께 쓴다.
- 메뉴는 현재 페이지 위에 작은 종이 패널로 열고, 바깥을 누르거나 Esc를 누르면 닫는다.
- 항목은 `내 스케치북 관리`, `친구에게 공유하기`, `새 스케치북 만들기` 순서다.
- `내 스케치북 관리`는 관리 세션이 없으면 PIN 입력 화면으로 자연스럽게 이어진다.

### 관리 페이지 `/m/{publicId}`

- 오른쪽의 아이콘형 친구 페이지 링크를 `☰ 메뉴`로 통일한다.
- 항목은 `친구 페이지 보기`, `스토리 이미지 만들기`, `공유하기`, `관리용 비밀번호 변경`, `로그아웃`이다.
- PIN 변경은 현재 PIN을 먼저 확인한 뒤 새 4자리 PIN과 선택 힌트를 받는다. 변경에 성공하면 이전 관리 세션을 모두 무효화하고 현재 기기에만 새 세션을 발급한다.
- 로그아웃은 현재 관리 세션 쿠키만 삭제하고 공개 페이지로 이동한다.

## UI 원칙과 상태

- 기존 650px 모바일 스케치북 폭, 종이 표면, 1px 연필선, 스케치 블루 CTA를 유지한다.
- 메뉴와 PIN 입력은 아이콘만으로 의미를 전달하지 않는다. 모든 행동은 한국어 텍스트 레이블을 사용하고 최소 44px 터치 영역을 가진다.
- PIN 입력: 초기, 힌트 있음, 잘못된 PIN, 잠김, 성공 후 관리 대시보드의 다섯 상태를 제공한다.
- 메뉴: 열림, 닫힘, 키보드 포커스, 메뉴 밖 클릭, Esc 닫힘을 지원한다.

## 구현 경계

- 데이터/도메인: 스케치북 타입, 생성 스키마, 저장소의 PIN 해시·힌트·실패 잠금 필드와 레거시 기본값 처리.
- 서버: PIN 로그인·로그아웃·변경 API, 관리 세션 검증, 페이지·관리 API의 일관된 권한 검사, 예전 복구 경로의 PIN 전환 처리.
- 클라이언트: 생성 폼, 생성 완료 화면, PIN 입력/변경 화면, 공개·관리 헤더 메뉴.
- 이번 범위에서는 이메일·소셜 로그인, 비밀번호 찾기, 운영자 문의, 다중 소유자, 결제 인증 변경을 다루지 않는다.

## 검증 기준

- 스키마가 4자리 외 입력과 과도한 힌트를 거절하고 PIN 평문을 저장하지 않는다.
- PIN이 없거나 틀리면 공개 URL로 관리 API와 관리 이미지를 조회·변경할 수 없다.
- 올바른 PIN으로만 세션이 발급되고, 5회 실패 후 잠기며 성공 시 실패 상태가 초기화된다.
- 새 스케치북 생성 응답과 완료 화면에 복구 토큰/링크가 없다.
- 기존 스케치북의 관리 토큰·복구 흐름은 PIN 설정 전까지 유지된다.
- 공개·관리 헤더의 메뉴는 텍스트 항목, 키보드 조작, 올바른 목적지 이동을 제공한다.

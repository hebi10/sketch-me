# 이미지 비용 최적화와 워터마크 상품 설계

## 목표

공개 갤러리의 이미지 전송량과 반복적인 Storage 다운로드를 줄이고, 기존 모의 결제 흐름에 워터마크 제거 상품을 추가한다. 현재의 서버 권한 검증, 모바일 최대 650px UI, 숨김·삭제 기능과 기존 데이터 호환성을 유지한다.

이번 범위에서 무료·유료 스케치북 자동 보관기간, 추가 스토리 테마, 이벤트 상품, 무제한 상품과 단체 상품은 구현하지 않는다.

## 확정 상품

| 상품 | 가격 | 효과 |
| --- | ---: | --- |
| 친구 그림 10명 추가 | 990원 | 참여 한도 10명 증가 |
| 친구 그림 50명 추가 | 4,490원 | 참여 한도 50명 증가 |
| 친구 그림 100명 추가 | 8,490원 | 참여 한도 100명 증가 |
| 워터마크 제거 | 990원 | 해당 스케치북의 스토리 결과 이미지에서 워터마크 제거 |

모든 결제는 기존과 동일한 모의 결제다. 상품 ID와 가격·효과는 서버에서 결정하며 요청 본문의 금액은 신뢰하지 않는다. 같은 요청 ID는 한 번만 처리한다.

## 이미지 저장 구조

새 친구 그림은 제출 시 다음 두 파일을 함께 만든다.

- 원본: `sketchbooks/{sketchbookId}/drawings/{drawingId}/original.webp`
  - 720×720, 현재 품질·350KB 상한 유지
- 썸네일: `sketchbooks/{sketchbookId}/drawings/{drawingId}/thumbnail.webp`
  - 320×320, WebP, 목록용 품질과 90KB 상한 적용

Firestore 그림 문서에는 `imagePath`와 선택적 `thumbnailPath`를 함께 저장한다. 신규 업로드에서 두 파일 중 하나라도 저장 또는 Firestore 등록에 실패하면 생성한 두 파일을 모두 정리한다.

기존 그림에는 `thumbnailPath`가 없다. 공개 썸네일 API가 기존 그림을 처음 요청받으면 원본을 검증·다운로드하여 320px 썸네일을 생성하고 결정적 경로에 저장한다. 동시에 같은 요청이 들어와도 같은 내용으로 덮어쓰는 방식이라 결과가 달라지지 않는다. 생성이 실패하면 그 요청에 한해 원본을 축소해 응답하되 원본 파일 자체를 갤러리 URL로 공개하지 않는다.

그림을 영구 정리할 때는 원본과 썸네일을 모두 삭제한다. 기존 그림은 선택 필드가 없어도 삭제할 수 있도록 결정적 썸네일 경로를 함께 정리한다.

## 공개 이미지 API와 캐시

공개 목록은 `/api/sketchbooks/{publicId}/drawings/{drawingId}/thumbnail?v={publicImageVersion}`를 사용한다. 스토리 합성과 관리 화면의 상세 사용은 기존 원본 API를 유지한다.

그림 문서에 `publicImageVersion`을 저장한다. 신규 그림은 생성 시 난수 버전을 받고, 숨김·삭제·운영자 차단·재공개처럼 공개 범위가 바뀔 때 새 버전으로 교체한다. 기존 문서는 `updatedAt`에서 파생한 호환 버전을 사용한다.

썸네일 API는 다음 순서로 처리한다.

1. 스케치북이 `PUBLIC`이고 운영 차단 상태가 아닌지 확인한다.
2. 그림이 `VISIBLE`이고 운영 차단 상태가 아닌지 확인한다.
3. 요청한 버전이 현재 공개 이미지 버전과 일치하는지 확인한다.
4. 썸네일 파일을 반환한다.

성공 응답은 `public, max-age=300, s-maxage=300, stale-while-revalidate=60`과 버전 기반 `ETag`를 사용한다. 404와 모든 관리·운영자 이미지는 `private, no-store`를 유지한다. 숨김 또는 삭제 전 URL이 외부 캐시에 남는 시간은 최장 약 5분이며, 새 페이지와 새 URL에서는 즉시 제외된다. 이 제한은 정책 문서와 운영 체크리스트에 명시한다.

원본 API는 스토리 제작에 필요하지만 공개 갤러리에서 호출하지 않는다. 원본의 공개 캐시는 이번 범위에서 확대하지 않아 차단 안전성을 우선한다.

## 워터마크 이미지와 결과물

이미지 생성 기능으로 투명 배경의 단색 연필 스케치 스타일 워터마크를 제작한다. 모티프는 펼친 스케치북과 비스듬히 놓인 연필이며, 작은 크기에서도 알아볼 수 있도록 선을 단순화한다. 생성 원본은 PNG로 보관하고 서비스용 WebP를 만들어 `public/brand` 아래에서 사용한다. SVG는 직접 만들지 않는다.

무료 스토리 결과물에는 하단 안전 영역에 워터마크 심볼과 `스캐치북` 텍스트를 낮은 불투명도로 표시한다. 텍스트는 이미지 생성 결과에 의존하지 않고 Canvas에서 기존 브랜드 글꼴로 그려 한글 깨짐을 방지한다. 워터마크는 BEST 그림이나 공유 URL을 가리지 않는다.

워터마크 제거 권한이 있으면 미리보기와 다운로드 결과에서 심볼·텍스트를 모두 생략한다. 해상도와 기존 테마는 무료·구매 사용자에게 동일하다.

## 권한과 데이터 모델

`PurchaseProductId`에 `WATERMARK_FREE`를 추가하고 구매 금액 타입을 새 가격에 맞게 확장한다. 인원 증가가 없는 상품을 표현할 수 있도록 `additionalLimit`은 `0 | 10 | 50 | 100`을 지원한다.

스케치북 문서에 `entitlements.watermarkFree`를 저장한다. 기존 문서는 필드가 없으면 `false`로 해석한다. 워터마크 상품 결제 트랜잭션은 구매 기록 생성과 권한 부여를 함께 수행한다. 재시도 또는 재구매 요청이 와도 권한은 `true`로 유지하고 참여 한도는 바꾸지 않는다.

스토리 페이지는 관리 세션이 검증된 서버에서 권한을 읽어 클라이언트 합성기에 전달한다. 클라이언트가 임의로 권한 값을 바꾸더라도 유료 결제를 위조해 서버 데이터가 변경되지는 않는다. 현재 결과물 생성 자체가 브라우저 Canvas 방식이므로 강한 DRM은 제공하지 않으며, 이는 모의 결제 단계의 제품 UX 검증 범위로 본다.

## 구매 UI

관리 화면의 결제 팝업은 `친구 인원 추가`와 `결과 이미지`로 상품을 구분한다. 워터마크 제거 상품은 효과가 영구 적용되는 단일 상품으로 표시한다. 이미 구매한 경우 선택을 비활성화하고 `적용됨` 상태를 보여준다.

스토리 제작 화면에는 무료 상태일 때 `워터마크 없이 저장하기 · 990원` 진입점을 제공한다. 기존 관리 권한을 사용해 동일한 모의 결제 API를 호출하고, 성공하면 화면 상태와 미리보기를 즉시 갱신한다. 중복 클릭, 실패 메시지, 포커스 복귀와 모바일 650px 너비를 기존 결제 팝업 패턴에 맞춘다.

## 비용 안전장치

`apphosting.yaml`의 `maxInstances: 1`은 유지한다. 저장소에는 Firebase App Hosting, Storage, Firestore 사용량 확인 항목과 Google Cloud Billing 예산 알림 설정 절차를 문서화한다.

예산 알림은 자동 차단이 아니므로 운영 설정 적용은 코드 배포와 분리한다. 실제 금액·알림 수신자·임계값은 해비님의 별도 승인 후 Firebase/Google Cloud 콘솔에서 설정한다. Cloud Run에는 월별 금액 기준의 완전한 하드캡이 없으므로 인스턴스 상한과 사용량 모니터링을 함께 사용한다.

## 정책 문서

서비스 이용 및 결제 안내에 네 상품의 모의 가격과 워터마크 제거 효과를 반영한다. 개인정보 처리방침은 썸네일을 별도 생성·저장한다는 점과 공개 이미지가 최대 5분 캐시될 수 있다는 점을 설명한다. 자동 보관기간과 자동 삭제는 이번 변경에 포함하지 않으며 현재의 직접 삭제 기준을 유지한다.

## 오류 처리와 호환성

- 썸네일 생성 실패가 원본 그림 제출을 불완전한 상태로 남기지 않도록 신규 업로드는 원본·썸네일을 함께 정리한다.
- 기존 그림의 지연 생성 실패는 원본을 메모리에서 축소한 응답으로 대체하며 Firestore 필수 필드로 승격하지 않는다.
- 캐시 버전이 없거나 일치하지 않는 공개 요청은 캐시 가능한 오류 대신 `private, no-store` 404를 반환한다.
- 숨김·삭제·운영 차단 시 공개 버전을 교체하고 관리·운영자 원본 API는 계속 인증과 `no-store`를 적용한다.
- 상품 가격과 권한은 서버 목록만 신뢰하고 구매 요청 ID로 멱등성을 유지한다.

## 검증

- 이미지 최적화 단위 테스트: 320×320 WebP, 용량 상한, 원본과 썸네일 동시 생성
- 저장소 경로 테스트: 썸네일 경로 생성·검증, 잘못된 경로 차단
- 제출 API 테스트: 두 파일 저장, 실패 시 두 파일 정리, Firestore 경로 기록
- 공개 썸네일 API 테스트: 상태·버전 검증, 캐시 헤더, 기존 그림 지연 생성, 404 `no-store`
- 관리·운영 변경 테스트: 숨김·삭제·차단·재공개 시 버전 갱신과 파일 정리
- 구매 테스트: 새 가격, 워터마크 권한 부여, 중복 요청 멱등성, 인원 한도 불변
- UI 테스트: 무료 워터마크, 구매 후 제거, 모바일 결제 팝업 접근성
- 전체 Vitest, TypeScript, ESLint, Next.js production build
- 모바일 Chrome에서 공개 갤러리의 썸네일 URL·크기, 캐시 헤더, 스토리 미리보기와 모의 결제를 직접 확인

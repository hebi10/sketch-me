# 스캐치북 전체 피드백 보완 설계

## 목표

모바일 핵심 흐름의 이탈·접근성 문제를 해결하고, 공개 베타에 필요한 운영 안전장치와 저장소 위생을 보완한다. 기존 650px 모바일 전용 구조, 스케치북 시각 언어, Firebase 서버 경유 정책과 모의 결제는 유지한다.

## 사용자 경험

### 그리기

- 전체 화면 우측 하단에 기존 `fullscreen-back.webp`를 사용하는 명시적 나가기 버튼과 기존 도구 버튼을 배치한다.
- 그림이 없으면 즉시 나가고, 작업이 있으면 확인 대화상자로 손실을 예방한다.
- Escape 키도 같은 종료 흐름을 사용한다.
- 포인터로 그리기 어려운 사용자는 PNG/JPEG/WebP 완성 그림을 불러와 제출할 수 있다.
- 파일 형식·2MB 제한과 오류를 인라인으로 안내하고, 불러온 이미지는 정사각 캔버스 안에 전부 보이도록 그린다.

### 스케치북 생성

- 이름·관리 PIN·힌트는 세션 초안으로 보존한다. 생성 성공 시 초안을 지운다.
- PIN 오류는 브라우저 기본 문구 대신 `관리 비밀번호는 숫자 4자리로 입력해 주세요.`로 안내한다.
- 선택 항목은 접힌 영역으로 시작해 필수 설정과 공유까지의 거리를 줄인다.

### 홈과 공개 스케치북

- 320×568에서도 핵심 CTA가 첫 화면에 보이도록 짧은 화면에서 콜라주 높이와 간격을 줄인다.
- 헤드라인은 `친구들이 보는 내 모습은?`으로 다듬는다.
- 그림이 0개면 BEST와 최근 영역을 숨기고 첫 참여를 유도하는 단일 빈 상태를 보여준다.
- 푸터 링크는 44px 이상의 터치 영역을 가진다.

### 관리 화면

- 관리자 데이터·이메일·금액은 시스템 고딕체로 표시하고 브랜드 워드마크만 손글씨를 유지한다.
- 관리 비밀번호 변경 UI는 네이티브 dialog, 포커스 이동·복귀, Escape 닫기를 지원한다.
- 디자인 값은 CSS 토큰으로 통합하되 기존 시각 결과를 바꾸지 않는다.

## 서버와 운영

- 스케치북 삭제 시작 시 먼저 상태를 `DELETED`로 바꿔 공개 접근을 차단한 뒤 Storage와 Firestore를 정리한다. 중간 실패 시 같은 관리 세션으로 재시도할 수 있어야 한다.
- Firebase App Check는 기본 비활성인 선택적 보호 장치로 추가한다. 공개 환경에서 서버·클라이언트 키가 모두 설정될 때만 토큰을 발급·검증하며, 미설정 개발 환경과 테스트는 기존 동작을 유지한다.
- App Check 오류는 401/503과 사용자 친화적 메시지로 구분한다.
- 개인정보 안내는 PIN 방식과 삭제 처리에 맞게 갱신한다.
- 운영 관리자 설정은 비밀값을 저장소에 넣지 않고 체크리스트로 유지한다.

## 저장소 정리

- npm을 단일 패키지 매니저로 유지한다.
- 우발적으로 생성된 pnpm 파일, 빈 우발 파일, Firebase 디버그 로그를 제거하고 디버그 로그 패턴을 무시한다.
- 실제 UI가 사용하지 않는 고용량 PNG 원본은 `public`에서 제거하고 WebP 결과만 제공한다.

## 검증

- 각 동작은 실패하는 테스트를 먼저 추가한 뒤 최소 구현으로 통과시킨다.
- 관련 Vitest, TypeScript, ESLint, production build, mobile Chrome E2E를 실행한다.
- 320×568과 390×844에서 홈, 생성, 공개 빈 상태, 그리기, 관리 대화상자를 직접 확인한다.

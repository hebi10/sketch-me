# 스캐치북 레퍼런스 시안 기반 전체 디자인 개편

## 목표

제공된 두 디자인 시안의 손으로 만든 스케치북 감성을 현재 서비스 전 화면에 일관되게 적용한다. 기존 Next.js·Firebase 기능과 데이터 구조는 유지하며, 홈·생성·공개·그림판·관리·스토리 화면을 최대 650px의 모바일 전용 구성으로 개편한다.

## 디자인 원칙

- 흰 화면, 짙은 잉크 선, 절제된 블루를 핵심 시각 언어로 사용한다.
- 실제 사용자 그림이 화면의 중심이 되며 장식은 콘텐츠를 방해하지 않는다.
- 테이프, 손그림 밑줄, 작은 연필 표시 등은 제한적으로 사용한다.
- 시안의 데스크톱 구성을 제거하고 280–650px 모바일 화면에 맞게 재배치한다.
- 한국어는 단어 중간에서 부자연스럽게 끊기지 않도록 유지한다.
- 기존 접근성 기준인 44px 터치 영역과 키보드 포커스를 보존한다.

## 생성 이미지 자산

ImageGen 내장 기능으로 다음 래스터 자산을 제작한다.

1. `public/brand/landing-sketch-collage.png`
   - 홈 화면용 네 장의 손그림 초상화 종이 카드 콜라주
   - 연필과 작은 별·곡선 낙서 포함
   - 글자와 워터마크 제외
   - 실제 친구 그림 데이터와 혼동되지 않도록 홈 장식에만 사용

## 공통 시각 시스템

- 배경: 별도 배경색과 배경 이미지를 사용하지 않는다. 모든 화면은 최대 650px 컨테이너로 중앙 정렬한다.
- 잉크: `#181818`, 보조 텍스트 `#6E6E6E`, 선 `#D8D3C9`를 유지한다.
- 포인트 블루: 주요 CTA와 BEST 배지에 `#506F8F`에 가까운 블루를 사용한다.
- 제목은 손글씨 인상을 주는 한국어 폰트 스택을 사용하되 가독성이 낮은 필기체는 본문에 사용하지 않는다.
- 카드 모서리와 테두리는 흰 종이 카드처럼 절제하고 과도한 그림자는 사용하지 않는다.
- 공통 헤더는 중앙 워드마크, 좌측 메뉴 또는 뒤로가기, 우측 공유 또는 문맥 행동의 구조로 통일한다.

## 화면별 설계

### 홈

- 상단에 핵심 문구, 중간에 ImageGen 초상화 콜라주, 하단에 블루 CTA를 배치한다.
- 모든 폭에서 문구 → 콜라주 → CTA 순서의 단일 열을 유지한다.

### 생성 화면

- 입력, 참고 사진, 본인 그림을 한 권의 스케치북을 만드는 단계처럼 구분한다.
- 섹션 번호 대신 짧은 제목과 안내 문구로 흐름을 설명한다.
- 제출 CTA를 포인트 블루로 통일한다.

### 공개 스케치북

- 상단에 중앙 워드마크와 공유 행동을 제공한다.
- 소개 문구와 생성자의 실제 그림을 테이프로 붙인 종이 사진처럼 배치한다.
- 친구 그림 전체 보드는 모바일 2열로 표시한다.
- 동일한 실제 그림 데이터에서 BEST 1~4와 최근 그림을 별도 구역으로 재구성한다.
- 친구 그림이 없거나 BEST가 부족한 경우 종이 슬롯 형태의 빈 상태를 표시한다.
- 주요 CTA는 보드 하단과 모바일 고정 영역에서 포인트 블루로 제공한다.

### 그림판

- 캔버스를 큰 종이 면으로 유지하고 참고 사진은 테이프가 붙은 레이어처럼 표현한다.
- 그림·참고사진·편집 탭과 도구는 시안의 하단 편집 패널처럼 정리한다.
- 기능은 현재 구현된 펜, 지우개, 색상, 굵기, 실행 취소, 다시 실행, 전체 삭제를 그대로 유지한다.
- 모바일 가로 화면의 캔버스·도구 좌우 배치를 유지한다.

### 관리 화면

- 참가 현황을 책 아이콘과 진행 막대가 포함된 종이 패널로 표현한다.
- 공유와 스토리 만들기 CTA를 시안과 같은 블루 계열로 통일한다.
- 친구 그림 카드는 모바일 2열을 기본으로 하며 BEST 배지를 명확히 표시한다.
- 공개·숨김·삭제·BEST 작업은 현재의 점진적 공개 구조를 유지한다.

### 스토리 화면과 결과물

- BEST 1을 크게, BEST 2~4를 하단 3열로 유지한다.
- 종이 질감, 손그림 밑줄, 블루 BEST 배지와 CTA를 적용한다.
- 다운로드 결과는 정확히 1080×1440(3:4)이며 실제 Firebase 이미지만 합성한다.

## 반응형 기준

- 280–650px에서 한글 단어 중간 줄바꿈과 가로 넘침이 없어야 한다.
- 모든 화면은 최대 너비 650px이며 브라우저 중앙에 배치한다.
- 공개 친구 그림과 관리 그림은 기본 2열이며 320px보다 좁을 때만 필요한 경우 1열로 축소한다.
- 650px보다 넓은 브라우저에서도 PC 전용 레이아웃으로 확장하지 않는다.
- 모바일 가로: 기존 캔버스·도구 좌우 배치를 유지한다.

## 데이터와 기능 경계

- Firestore 문서 구조, Storage 경로, API 계약은 변경하지 않는다.
- 공개 화면의 BEST와 최근 구역은 기존 `Drawing.bestRank`, `createdAt`, `status` 값을 사용한다.
- 생성 이미지 자산은 정적 장식에만 사용하고 사용자 생성 그림을 대체하지 않는다.
- 모의 결제, 관리 복구, 삭제, 공개 상태, BEST 지정 기능은 현재 동작을 유지한다.

## 검증 기준

- 기존 Vitest 전체 통과
- 기존 생성 → 친구 제출 → 관리 → BEST → PNG Playwright 흐름 통과
- 280px, 320px, 390px, 650px에서 가로 넘침 없음
- 주요 터치 대상 44px 이상
- 홈·생성·공개·그림판·관리·스토리의 Chrome 스크린샷을 한 번의 배치로 검토
- Impeccable detector 실행 후 치명적 UI 문제 없음
- Next.js 프로덕션 빌드 통과

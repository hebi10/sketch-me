# 비용 안전성과 보관 정책 설계

## 목표

공개 스케치북 생성 남용과 무료 이미지의 무기한 누적을 제한하면서, 유료 구매자의 최소 1년 이용 보장과 서비스 운영 중 보관 약속을 유지한다.

## 생성 제한

- IP별 스케치북 생성은 1시간에 3개, 72시간에 9개로 제한한다.
- 서비스 전체 생성은 1시간에 60개로 제한한다.
- 세 제한은 Firestore 트랜잭션 하나에서 함께 판정해 App Hosting 인스턴스 수와 무관하게 적용한다.
- IP 원문은 저장하지 않고 서버 비밀키를 사용한 HMAC-SHA256 결과만 문서 키로 사용한다.
- 제한 문서에는 만료 시각을 기록하고 Firestore TTL을 적용한다.
- Firestore 또는 비밀키 설정이 실패하면 생성 요청을 허용하지 않고 일반적인 503 응답을 반환한다.
- 친구 그림 제출 제한은 기존 메모리 정책을 유지한다.

## 보관 정책

- 정책 시행 후 새로 생성되는 무료 스케치북은 생성일로부터 달력 기준 6개월 뒤 만료한다.
- 결제가 성공하면 상품 종류와 관계없이 유료 보관으로 전환한다.
- 유료 스케치북은 최근 결제일로부터 최소 1년을 보장하고 서비스 운영 중 계속 보관한다.
- 기존 스케치북은 종전 약속을 보존하기 위해 자동 만료 대상으로 소급 전환하지 않는다.
- 관리 화면은 무료 만료일을 항상 표시하고, 30일 이내에는 삭제 예정 상태를 명확히 강조한다.
- 유료 스케치북은 최소 보장일과 서비스 운영 중 계속 보관됨을 표시한다.

## 자동 삭제

- 보호된 내부 Route Handler를 Cloud Scheduler가 하루 한 번 호출한다.
- 정리 작업은 먼저 이전 실행에서 남은 시스템 삭제 작업을 재시도한 다음 새 만료 대상을 가져온다.
- 대상마다 스케치북 트리 밖에 삭제 작업을 보존하고 공개 상태 차단, Storage 접두사 삭제, Firestore 재귀 삭제, 작업 문서 삭제 순서로 처리한다.
- 한 대상의 실패가 다른 대상의 정리를 막지 않으며 응답에는 성공·실패 개수만 포함한다.
- 결제·계약 기록의 법정 보존은 콘텐츠 자동 삭제와 분리한다.

## 운영 설정

- `PUBLIC_MUTATION_RATE_LIMIT_SECRET`은 IP 해시 전용 비밀키다.
- `RETENTION_CLEANUP_SECRET`은 내부 정리 API의 Bearer 인증 비밀키다.
- Cloud Scheduler는 `POST /api/internal/retention-cleanup`을 호출하고 위 비밀키를 전달한다.
- 예산 알림과 Cloud Run 지출 한도는 Firebase 콘솔과 Google Cloud 콘솔에서 별도로 설정한다.

## 정책 문구

- 이용약관에는 무료 6개월 보관, 만료 전 관리 화면 안내, 유료 최소 1년 보장과 운영 중 보관을 명시한다.
- 개인정보 처리방침에는 생성 제한 해시를 최대 72시간 처리한다는 점과 무료 콘텐츠 자동 파기 기준을 명시한다.
- 기존 유료 이용자의 종전 조건을 유지한다.

## 검증

- 제한 경계, 동시 트랜잭션 상태, 72시간 초기화와 503 실패 닫힘을 단위 테스트한다.
- 달력 기준 6개월·1년 계산, 신규 무료 초안, 결제 전환을 단위 테스트한다.
- 내부 정리 API 인증, 재시도 가능한 삭제 순서와 부분 실패를 단위 테스트한다.
- 관리 화면과 정책 페이지 문구를 UI 테스트한다.
- 관련 테스트, 전체 테스트, 린트, 빌드를 실행한다.

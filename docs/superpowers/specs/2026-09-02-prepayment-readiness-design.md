# 결제 연결 전 운영 준비 설계

## 목표

실결제 키와 사업자 정보가 아직 없는 상태에서도 현재 베타 서비스를 안전하게 운영할 수 있도록 보안 경계, 장애 복구, 배포 검증, 결제 전환 경계를 정리한다. 실제 과금은 명시적인 운영 설정과 Toss 자격 증명이 모두 준비되기 전까지 활성화하지 않는다.

## 범위

- 공개 이미지 응답이 해당 스케치북의 Storage 경로와 허용된 이미지 MIME만 사용하도록 검증한다.
- 관리 PIN 실패 횟수 갱신을 Firestore 트랜잭션으로 직렬화한다.
- 새 공개 ID의 엔트로피를 높이고 생성 실패 시 저장된 스케치북과 이미지를 정리한다.
- 예상하지 못한 서버 오류의 원문을 클라이언트에 노출하지 않는다.
- 모의 결제는 개발·테스트에서만 허용하고 운영에서는 결제 준비 상태를 명확히 안내한다.
- 로컬 빌드를 오염시키는 임시 산출물 참조를 제거하고 CI에 린트·테스트·빌드·에뮬레이터 검증을 둔다.
- CSP/HSTS 등 기본 보안 헤더와 운영 체크리스트를 추가한다.

## 결제 경계

결제 모드는 `disabled`와 `mock` 두 단계로 둔다. 기본값은 `disabled`이며 `mock`은 production에서 거부한다. Toss 연동은 주문 생성, 승인, 웹훅, 취소, 대사, 환불 정책과 사업자 고지 정보가 함께 확정될 때 별도 단계로 활성화한다. 이 설계는 미완성 PG 호출이 운영에서 과금처럼 보이는 상황을 방지한다.

## 데이터와 보안

- 기존 스케치북·그림·모의 결제 데이터 형식은 유지한다.
- 공개 이미지의 Storage 객체 경로는 도메인 객체 ID로 재구성한 허용 경로와 일치해야 한다.
- PIN 잠금 문서는 트랜잭션에서 읽고 갱신하여 동시 요청으로 실패 횟수가 유실되지 않게 한다.
- 공개 ID는 UUID 전체 엔트로피를 사용하고 저장 전 충돌을 재확인한다.
- 예기치 않은 서버 오류는 일반화된 한국어 메시지와 500 상태로 응답한다.

## 운영 설정

Firestore 인덱스, 백업/PITR, 삭제 보호, 알림 정책은 코드와 런북에 정의하되 비용과 운영 대상이 수반되는 실제 변경은 별도 배포 단계로 남긴다. App Check도 배포 키와 Firebase 콘솔 enforcement를 함께 설정해야 하므로 체크리스트에서 검증한다.

## 검증

- 변경 동작은 실패 테스트를 먼저 추가한다.
- 단위 테스트, 린트, 타입 검사, 프로덕션 빌드를 실행한다.
- Firestore/Storage 에뮬레이터 통합 테스트와 핵심 모바일 E2E를 실행한다.
- UI 변경 대상은 Impeccable 정적 검사를 한 번 실행하고 실제 브라우저에서 확인한다.

## 완료 기준

코드와 자동화 검증이 통과하고 운영에서 모의 결제가 실행될 수 없으며, 실제 결제 활성화에 필요한 외부 입력과 콘솔 작업이 하나의 체크리스트로 추적된다.

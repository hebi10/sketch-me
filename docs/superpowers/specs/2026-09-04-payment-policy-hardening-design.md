# 결제 정책 및 거래 보존 강화 설계

## 목표

페이앱 결제의 승인·부분취소·전액취소 상태를 정확하게 기록하고, 스케치북 삭제와 무관하게 법정 거래 기록을 보존하며, 구매자가 결제 전후에 청약철회·환불·판매자 정보를 명확히 확인할 수 있도록 한다.

## 범위

- 법정 보관용 거래 장부 분리
- PayApp 상태 및 취소 금액 모델 보완
- 전액취소 시 구매 혜택 회수
- 결제 동의와 약관·개인정보 처리방침 보완
- 인쇄 가능한 결제 영수증 화면 제공
- 사업자 연락처·통신판매업 정보와 과세 유형의 운영 설정 검증
- 관련 단위·통합·화면 테스트와 브라우저 검증

운영 PayApp 비밀값 생성, 통신판매업 신고, 세무 유형 결정은 코드 변경 범위에 포함하지 않는다. 코드에서는 실제 값이 준비되기 전 운영 결제가 활성화되지 않도록 검증하고 설정 방법을 문서화한다.

## 권장 구조

### 운영 주문과 법정 거래 장부

기존 `sketchbooks/{sketchbookId}/purchases/{requestId}` 문서는 관리 화면과 혜택 적용에 사용하는 운영 주문으로 유지한다. 새 최상위 `legalTransactionRecords/{orderId}` 컬렉션을 법정 보관용 장부로 추가한다.

운영 주문을 생성하거나 상태가 바뀔 때 같은 Firestore 트랜잭션 안에서 거래 장부도 함께 생성·갱신한다. 장부에는 다음 최소 정보만 저장한다.

- 주문번호, 페이앱 주문번호와 결제수단 유형
- 상품 ID, 결제금액, 취소금액과 결제 상태
- 스케치북 내부 ID와 공개 ID
- 휴대전화번호 끝 4자리
- 디지털 콘텐츠 즉시 제공 동의 및 미성년자 관련 확인 시각·문구 버전
- 주문 생성, 결제 완료, 취소 요청, 부분취소, 전액취소 시각
- PayApp 원본 상태 코드와 마지막 갱신 시각
- 법정 보관 만료 예정일

전체 휴대전화번호, PayApp 연동 비밀값, 결제수단 상세정보, 그림과 메시지는 장부에 저장하지 않는다.

기존 주문은 스케치북 삭제 직전에 장부로 이관한다. 이관이 실패하면 스케치북 Firestore 트리를 삭제하지 않아 거래 기록 유실을 방지한다. 장부 기록은 스케치북과 Storage 콘텐츠 삭제 대상에서 제외한다.

## 결제 상태 모델

구매 상태에 `PARTIALLY_CANCELLED`를 추가한다. PayApp 상태는 다음 규칙으로 처리한다.

- `1`, `10`: 결제 요청 또는 처리 대기인 `READY`
- `4`: 검증 완료 후 `SUCCEEDED`
- `8`, `16`, `31`, `32`: 결제 요청 취소인 `CANCELLED`
- `9`, `64`: 승인 전액취소인 `CANCELLED`
- `70`, `71`: `PARTIALLY_CANCELLED`
- 그 밖의 상태: 오판을 피하기 위해 `REVIEW_REQUIRED`

모든 통보는 원본 PayApp 상태 코드를 기록한다. 부분취소 통보는 취소금액을 검증하고 누적 취소금액이 원 결제금액을 넘지 않도록 한다. 금액 누락·불일치·알 수 없는 상태는 자동으로 혜택을 변경하지 않고 관리자 확인 대상으로 남긴다.

## 혜택 적용과 회수

결제 성공 시 기존과 같이 한 번만 혜택을 적용한다. 전액취소 시 `benefitAppliedAt`이 있고 `benefitRevokedAt`이 없는 주문에 대해서만 한 번 회수한다.

- 추가 인원 상품: 현재 참여자 수와 무료 기본 한도 10보다 낮아지지 않는 범위에서 구매한 추가 한도를 차감한다. 이미 제출된 그림은 삭제하지 않으며, 취소 후 한도를 초과한 경우 신규 제출만 차단한다.
- 워터마크 제거 상품: 같은 스케치북에 취소되지 않은 다른 워터마크 제거 구매가 없을 때만 권한을 해제한다.
- 부분취소: 상품 혜택을 자동 분할하기 어렵기 때문에 혜택은 즉시 회수하지 않고 `benefitAdjustmentRequired`를 기록하여 관리자 화면에서 확인하게 한다.

전액취소 통보가 중복되어도 한도나 권한을 두 번 회수하지 않는다. 취소 API 성공 후 피드백이 지연될 수 있으므로 취소 요청 시각과 공급자 상태를 관리자 화면에 분리해 표시한다.

## 결제 전 동의

기존 즉시 제공 동의를 다음 두 확인으로 분리한다.

1. 무료 10명 이용 또는 워터마크 미리보기를 확인했으며, 결제 완료 즉시 디지털 혜택 제공이 시작되어 관련 법령이 정한 경우 청약철회가 제한될 수 있다는 동의
2. 구매자가 미성년자가 아니거나, 미성년자인 경우 법정대리인의 동의를 받았다는 확인

두 확인은 서버에서도 필수로 검증하고 각각 시각과 문구 버전을 주문 및 거래 장부에 기록한다. 결제 화면에는 7일 청약철회 원칙, 상품이 계약 내용과 다를 때의 권리, 환불 신청 방법으로 연결되는 링크를 제공한다.

## 정책 문서와 판매자 고지

서비스 이용 및 결제 안내에는 다음 내용을 명시한다.

- 계약 내용 수령일부터 7일 이내 청약철회 원칙
- 즉시 공급되는 디지털 콘텐츠의 제한 조건과 무료 체험·미리보기 범위
- 표시·광고 또는 계약과 다른 공급에 대한 별도 청약철회 권리
- 청약철회 접수일을 기준으로 한 환불 처리 기한
- 결제수단 자체 취소 제한과 판매자의 법정 환불 의무가 별개라는 점
- 미성년자와 법정대리인의 계약 취소 권리
- 이메일을 통한 청약철회·환불 신청 항목

판매자 정보에는 고객센터 전화번호와 통신판매업 신고번호를 표시한다. 신고 면제 대상이면 번호 대신 정확한 면제 사유를 표시한다. 실제 값은 공개 환경변수로 주입하며 둘 중 어느 정보도 준비되지 않은 운영 환경에서는 결제를 시작하지 않는다.

개인정보 처리방침에는 운영 주문과 분리된 거래 장부, 저장 항목, 5년 보관, 스케치북 삭제 시 콘텐츠와 거래 기록의 분리 삭제를 명시한다.

## 영수증 및 환불 신청

결제 결과 화면을 관리 세션으로 보호되는 전자 영수증으로 확장한다. 화면에는 다음 정보를 표시한다.

- 결제 상태와 상품명
- 주문번호, 결제금액과 결제수단
- 주문일, 결제 완료일, 취소일과 부분취소 금액
- 판매자 상호·대표자·사업자등록번호·주소·전화번호·이메일·통신판매업 정보
- 청약철회·환불 기준과 정책 문서 링크

영수증은 브라우저 인쇄 기능으로 인쇄하거나 PDF로 저장할 수 있게 한다. 이메일 환불 신청 링크에는 주문번호와 스케치북 공개 ID를 미리 채우며, 사용자가 결제수단·요청 사유·환불 계좌가 필요한 경우의 연락 방법을 직접 작성하도록 안내한다. 환불 계좌는 서비스 서버에 저장하지 않는다.

## 세금 및 운영 설정

`PAYAPP_TAX_MODE`를 `TAXABLE` 또는 `TAX_FREE` 중 하나로 명시해야 결제 요청을 만들 수 있게 한다. 과세 모드에서는 소비자 표시가격을 최종 결제금액으로 유지하면서 과세 공급가액과 부가세를 PayApp 요청에 전달하고, 면세 모드에서는 면세금액을 전달한다. 실제 적용 모드는 세무 확인 후 운영 환경에 설정한다.

운영 결제 활성화에 필요한 설정은 다음과 같다.

- `PAYAPP_USER_ID`
- `PAYAPP_LINK_KEY`
- `PAYAPP_LINK_VALUE`
- `NEXT_PUBLIC_APP_URL`
- `PAYAPP_TAX_MODE`
- `NEXT_PUBLIC_BUSINESS_PHONE`
- `NEXT_PUBLIC_MAIL_ORDER_REGISTRATION_NUMBER` 또는 `NEXT_PUBLIC_MAIL_ORDER_EXEMPTION_REASON`

설정값은 로그나 클라이언트 응답에 노출하지 않는다. 공개 사업자 정보만 페이지에 렌더링한다.

## 오류 처리

- 거래 장부 기록 실패: 주문 상태 변경이나 스케치북 삭제를 완료하지 않고 재시도 가능한 오류로 반환
- 잘못된 취소금액: 상태를 `REVIEW_REQUIRED`로 기록하고 혜택 유지
- 중복 성공·취소 통보: 이미 적용·회수된 혜택을 다시 변경하지 않음
- 영수증 조회 권한 없음: 결제 정보 없이 403 반환
- 주문을 찾을 수 없음: 결제 정보 없이 404 반환
- 운영 설정 누락: 외부 결제 요청 전에 일반화된 설정 오류 반환

## 검증

- PayApp 각 상태 코드와 알 수 없는 상태 매핑 단위 테스트
- 부분취소 금액 검증과 누적 금액 테스트
- 성공 후 전액취소 시 추가 인원 및 워터마크 권한 회수 테스트
- 중복 취소 시 혜택 중복 회수 방지 테스트
- 스케치북 삭제 전 기존 주문 장부 이관 및 이관 실패 시 삭제 중단 테스트
- 결제 API의 두 필수 동의 서버 검증 테스트
- 영수증 API와 화면의 주문·판매자·환불 정보 테스트
- 약관·개인정보 처리방침·사업자 고지 테스트
- 결제 관련 단위 테스트, 전체 린트, 타입 검증이 포함된 프로덕션 빌드
- 결제 동의와 영수증을 모바일·데스크톱에서 브라우저 확인

## 완료 조건

- 스케치북을 삭제해도 결제 법정 장부가 유지된다.
- PayApp 부분취소와 알 수 없는 상태가 전액취소나 실패로 잘못 처리되지 않는다.
- 전액취소 혜택이 한 번만 회수되고 기존 그림은 삭제되지 않는다.
- 구매자가 결제 전 권리와 제한을 확인하고, 결제 후 주문 증빙과 환불 경로를 확인할 수 있다.
- 실제 사업자 연락처·통신판매업 정보·과세 유형이 없으면 운영 결제가 활성화되지 않는다.
- 관련 자동화 테스트와 빌드가 통과하며 화면 검증에서 치명적인 접근성·반응형 문제가 없다.

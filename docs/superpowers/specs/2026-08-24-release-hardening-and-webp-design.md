# 스캐치북 출시 하드닝 및 WebP 저장 설계

## 목표

현재 모바일 MVP를 소규모 공개 베타에 올릴 수 있는 수준으로 보완한다. 핵심 기준은 Firebase 무료 할당량 보호, 공유 성공률, 정원 마감의 사전 안내, 개인정보 삭제 가능성, 모바일 이미지 전송량 절감이다.

## 범위

### 이미지 저장

- 새로 저장되는 본인 그림, 친구 그림, 참고 사진은 클라이언트가 보낸 형식과 관계없이 서버에서 WebP로 재인코딩한다.
- 본인·친구 그림은 최대 720×960, 품질 76을 기본으로 한다.
- 참고 사진은 회전을 보정하고 최대 1280×1280, 품질 72로 줄인다.
- 입력은 2MB 이하, 최대 16메가픽셀만 허용한다. 변환 실패 파일은 저장하지 않는다.
- 스케치 이미지는 보통 30~150KB를 목표로 하되 복잡도에 따라 달라질 수 있으므로 100KB 이하를 계약처럼 보장하지 않는다. 서버 출력 상한은 스케치 350KB, 참고 사진 600KB로 두고 초과 시 더 낮은 품질로 한 번 재인코딩한다.
- 새 Storage 경로 확장자는 `.webp`를 사용한다. 기존 PNG/JPEG 레코드는 DB에 저장된 기존 경로로 계속 제공한다.
- 랜딩 콜라주는 WebP 파일을 추가해 그 파일을 제공한다. 기존 PNG는 파괴적 파일 삭제 승인 없이 유지한다.
- Instagram 공유용 다운로드는 사용자가 받는 최종 결과물이므로 1080×1440(3:4) PNG를 유지한다.

### 무료 할당량 보호

- `POST /api/sketchbooks`와 `POST /api/sketchbooks/[publicId]/drawings` 앞에 메모리 기반 고정 윈도 요청 제한을 적용한다.
- App Hosting의 `maxInstances: 1` 구성에서 IP별 생성 3회/시간, 그림 제출 20회/시간, 인스턴스 전체 생성 60회/시간, 제출 600회/시간을 기본값으로 한다.
- 프록시 IP 헤더는 첫 번째 유효 IP만 사용하며 값은 프로세스 메모리에만 보관한다. 재시작 시 초기화되는 제한은 베타 단계의 방어선이며, 정식 공개 전 CAPTCHA/App Check를 추가할 운영 항목으로 문서화한다.
- 제한 응답은 `429`와 `Retry-After`를 반환하고 사용자에게 다시 시도할 시간을 설명한다.

### 공유와 참여 마감

- 관리 화면의 `친구에게 공유하기`는 Web Share API를 우선 사용하고, 미지원 환경에서는 공개 링크를 클립보드에 복사한다.
- 공유 성공·실패를 live region으로 알린다.
- 참여 인원이 한도에 도달하면 공개 페이지의 그리기 CTA를 마감 상태로 바꾸고, 그리기 URL 직접 접근에서도 캔버스 대신 마감 안내를 보여준다.
- 제출 직전 경쟁 상태는 기존 서버 트랜잭션이 최종 방어한다.
- 그림 제출 완료 화면에는 `내 스케치북 만들기` CTA를 제공한다.

### 개인정보와 삭제

- `/privacy`에 수집 데이터, 이용 목적, 보관 기준, 공개 범위, 삭제 방법을 설명한다.
- 관리 화면에 명시적 확인을 거치는 `스케치북 전체 삭제` 동작을 추가한다.
- 삭제 API는 관리 쿠키를 확인한 뒤 Storage의 해당 스케치북 prefix와 Firestore 문서·하위 컬렉션을 제거하고 관리 쿠키를 만료한다.
- 삭제 중 실패하면 성공으로 표시하지 않으며 다시 시도할 수 있는 오류를 보여준다.

### 발견성, 오류, 접근성, 결과물

- 공개 스케치북은 이름 기반 title/description/Open Graph 메타데이터를 생성한다. 절대 URL 기준은 `NEXT_PUBLIC_APP_URL`로 설정한다.
- 전역 loading, error, not-found 화면을 추가하고 홈 또는 재시도 행동을 제공한다.
- 색상 스와치는 한국어 색상명으로 읽히게 하고 12px 미만의 보조 텍스트를 제거한다.
- Story PNG는 현재 디자인 토큰(`#506f8f`, 흰 종이, 한국어 시스템 글꼴)을 사용한다.
- 랜딩 하단에 개인정보 처리방침 링크를 제공한다.

### 운영 문서

- README에 로컬 실행, 에뮬레이터, 검증, 배포 환경 변수, Firebase 예산 알림, App Check/CAPTCHA 전환 조건, 장애 확인 항목을 기록한다.
- 외부 키가 없는 상태에서 Sentry, CAPTCHA, 이메일 알림을 가짜로 연결하지 않는다.

## 제외 범위

- 실제 결제 연동은 기존 모의 결제를 유지한다.
- 별도 관리자 계정과 전체 운영 대시보드는 인증 체계가 필요한 다음 단계로 남긴다.
- 기존 Storage 파일의 일괄 마이그레이션은 하지 않는다.

## 검증 기준

- 이미지 최적화 단위 테스트에서 출력 형식, 최대 치수, 상한 용량을 검증한다.
- 요청 제한 단위 테스트에서 허용, 차단, 윈도 만료를 검증한다.
- 기존 전체 단위·통합 테스트, 린트, 빌드가 통과한다.
- Firebase 에뮬레이터 E2E에서 생성, 그림 제출, BEST, Story PNG, 전체 삭제까지 검증한다.
- 280·320·390·650px에서 가로 넘침과 제목 줄바꿈이 없고, 주요 터치 영역이 44px 이상이다.
